# くばるAI v2 — 札幌の観光の「配分窓口」

AIエージェントが旅行者の代わりに旅程を組み、予約まで済ませる時代に向けた窓口です。

- 混雑マップのように「空いている所を見せる」と、同じ情報を読んだAIが一斉に同じ所へ集まります(機械の速さで起きる群集行動)。
- くばるAIは、エリア×時間帯ごとに住民と決めた**受け入れ上限**を持ち、問い合わせが来た順に体験の枠を**配ります**。埋まった枠は次の人に出しません。
- エージェントは MCP でつなぎます。旅行者の希望を自由文で渡すだけで、上限を守った旅程が返ってきて、15分間仮押さえされます。

> 上限・ふだんの人出・体験の一覧などの数値は、すべてデモ用の仮の値です。

## 枠の定義

**枠 = 窓口がその場所・時間帯に送る人数の上限。** 実際にそこにいる人数のことではありません。

| | 予約型(7体験) | 案内型(15体験) |
|---|---|---|
| 例 | 地元の人と会う体験、ジンギスカン店 | 公園、市場、街歩き、温泉、ロープウェイ |
| 窓口ができること | 席を確保できる(管理は確実) | すすめる人数を絞れるだけ |
| 送れる人数 | 席の残り と エリアの残り の小さい方 | エリアの残り − 安全の余裕(上限の2割) |
| 確定すると | 席が押さえられる | 案内人数として記録(入場の保証ではない) |

エリアの残り = 上限 − ふだんの人出(予測) − 窓口が送った人数。
案内型は、予測のはずれや案内に従わない人がいても上限を超えないよう、余裕を残して案内します。

## ネットに公開する(スマホ・どのClaudeからでも)

`server.py` を動かすと、1つのURLで「AIエージェント用の窓口(/mcp)」と「スマホでも見られるライブ画面(/)」が使えます。
無料で公開する手順は **DEPLOY.md** を見てください(GitHub + Render、30分ほど)。

```bash
pip install -r requirements-server.txt
python server.py          # http://localhost:8000/ がライブ画面、/mcp が窓口
```

## 中身

| ファイル | 役割 |
|---|---|
| `server.py` | ネット公開版。/mcp(窓口)と /(ライブ画面)を1つのサーバーで出す |
| `mcp_server.py` | AIエージェント向けの入口(MCPサーバー、PCのClaude Desktop用) |
| `kubaru/ai.py` | 希望文の読み取り(APIキーがあればClaude、なければキーワード) |
| `kubaru/dashboard.html` | ライブ画面 |
| `app.py` | デモ画面(Streamlit): 殺到テスト・窓口に頼む・窓口の状態・ルール |
| `kubaru/window.py` | 配分エンジン(上限・仮押さえ・確定・取消) |
| `kubaru/rush.py` | エージェント殺到テスト(混雑マップを読むAI vs 窓口に聞くAI) |
| `data/*.json` | エリア・体験・旅行者の仮データ |
| `state/bookings.json` | 予約の記録(画面とMCPサーバーが同じものを見る) |

## 動かし方

```bash
pip install -r requirements.txt
streamlit run app.py
```

## AIエージェントからつなぐ

**Claude Code**

```bash
claude mcp add kubaru -- python /path/to/kubaru_v2/mcp_server.py
```

**Claude Desktop**(`claude_desktop_config.json`)

```json
{"mcpServers": {"kubaru": {"command": "python", "args": ["/path/to/kubaru_v2/mcp_server.py"]}}}
```

つないだら、たとえば「札幌に2泊3日で行く。海鮮が好きで人混みは苦手。くばるで旅程を組んで」と頼みます。

| ツール | すること |
|---|---|
| `get_rules` | 配分ルールとエリアごとの上限 |
| `list_experiences` | 配れる体験(2〜3時間)の一覧 |
| `get_availability` | 日・時間帯ごとの残り枠と混雑率 |
| `request_plan` | 希望(自由文)から旅程を配って仮押さえ(15分) |
| `confirm_booking` / `cancel_booking` | 確定 / 取消 |
| `reset_demo` | 予約を全部消す(デモ用) |

デモでは、Streamlitの「③ 窓口の状態」を横に開いておくと、エージェントが予約するたびに枠が埋まっていく様子が見えます(「更新」を押す)。

## 殺到テストの結果(200人・3日間・乱数のたね0)

現実のずれを入れた条件: 案内に従う人70%、ふだんの人出の予測のはずれ±15%、安全の余裕20%。

| | 上限を超えたコマ | 上限を超えた人数(延べ) | 最大混雑率 | 旭山の最大 | 好みとの一致 |
|---|---|---|---|---|---|
| A. 混雑マップを読むAI | 6 | 60 | 210% | 210% | 4.23 |
| B. くばる窓口に聞くAI | 0 | 0 | 95% | 95% | 4.12 |

同じ条件で安全の余裕を0にすると、Bでも上限を超えるコマが1つ出ます(余裕が効いている)。
好みとの一致が少し下がるのは、予約型の席数に限りがあるためです。図は `results/` に入っています。

## これから

- 今はMCPだけ。将来はAIが予約・購入まで行う共通規格(GoogleのUCPなど)にも同じ窓口を出す想定です。
- 上限の数値は住民・事業者と決めるもの。デモの値は仮置きです。
- 予約の記録はJSONファイル1つ。本番ではデータベースと同時アクセス対策が必要です。
